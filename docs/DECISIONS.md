# Decisions

One line each: date · what · why.

- 2026-11-21 · Next.js 16 + Tailwind + shadcn/ui on Vercel · fastest path to a live demo link.
- 2026-11-21 · Placeholder name `bostonhacks-2026` and pages Home / Main app / About · idea not picked yet; rename later.
- 2026-11-21 · Board-game look: one dark "game table" theme (no light/dark toggle), Fredoka + Press Start 2P fonts, 3D feel from solid navy offset shadows and CSS 3D dice · matches the cover-art and toy-piece reference photos; all colours live as tokens in `globals.css`.
- 2026-11-21 · Idea picked: T Party (gamified MBTA feedback) · see docs/SPEC.md.
- 2026-11-21 · Keep Next.js instead of the spec's React + Vite · the repo, CI and Vercel setup already exist on Next.js.
- 2026-11-21 · Renamed `main-app` to `explore`, route `/app` to `/explore`, and added `my-challenges`, `rewards`, `challenge` folders · they match the five screens in the spec.
- 2026-11-21 · No `/challenges/[id]` route yet · Cache Components needs `generateStaticParams` or Suspense for dynamic routes; the challenge owner decides how.
- 2026-11-21 · A Quest = one live MBTA accessibility alert (elevator, escalator, access), built automatically in `src/lib/mbta.ts` · real, verifiable, self-updating; no hand-kept challenge list.
- 2026-11-21 · `/api/quests` caches MBTA for 5 minutes and falls back to a saved snapshot (`src/lib/data/`) · demo must not depend on MBTA being up.
- 2026-11-21 · Every auto-built Quest is labelled `community_mission`, never official · we must not invent official MBTA comment requests.
- 2026-11-21 · Shared database on Tiger Data (Postgres), tables in `src/lib/data/schema.sql` · localStorage cannot produce KPIs or show feedback to anyone else.
- 2026-11-21 · A fix = an open outage missing from a successful live MBTA fetch; snapshot or empty fetches never resolve anything · an MBTA hiccup must not fake fixes.
- 2026-11-21 · Tokens are counted from completed submissions (one per rider per quest), not stored · double rewards impossible.
- 2026-11-21 · Photos are not stored on the server, only `has_photo` · avoids keeping faces and locations.
- 2026-11-21 · AI check uses Gemini, lite model first with fallbacks (`src/lib/ai.ts`) · bigger models were overloaded (503) on demo weekend; lite answered in about 1 s.
- 2026-11-21 · Pass rule (every score 3 or more out of 5) is in code, and only `/api/review` can write an AI result · the model and the browser cannot grant a pass.
- 2026-11-21 · Editing a report after a check resets it to not checked; completion needs the exact checked report · spec: changes must be re-checked.
- 2026-11-21 · Loaded 26,300 closed outages (2019 onward) from MBTA's public LAMP alert archive, marked `source = 'archive'` · time-to-fix needs history; our own sync only started today.
- 2026-11-21 · Archive rows with no close time are skipped · in the archive that does not reliably mean still open.
- 2026-11-21 · `/api/stats` computes every KPI from the database on request, medians not averages · a few multi-year outages would distort an average.
- 2026-11-21 · MBTA's API drops closed alerts, so exact close times exist only in the archive; our own detected fixes carry a window (`last_seen_at` to `resolved_at`) and count toward time-to-fix only if that window is 30 minutes or less · fix times must not depend on our traffic.
- 2026-11-21 · `.github/workflows/sync.yml` loads `/api/quests` on the live site every 5 minutes · keeps detection windows small when nobody is using the app.
- 2026-11-21 · AI check capped at 20 per rider and 60 per network address per hour (address stored only as a hash) · protects the Gemini quota; does not stop invented user ids from earning tokens.
- 2026-11-21 · Quests widened from accessibility only to station issues, station closures, shuttles and suspensions on the subway; delays and bus alerts left out · delays vanish in minutes, bus stops are not on the map.
- 2026-11-21 · Alerts that have not started yet are not quests · nothing to see at the station; also keeps planned work out of "open now".
- 2026-11-21 · Verify quests: elevators and escalators MBTA closed in the last 24 h; one answer per rider (`verifications` table), 5 tokens, no AI check · gives riders a role MBTA cannot fill itself, and is quick enough for a platform wait.
- 2026-11-21 · Stations (`src/lib/data/stations.json`, real lat/lon and route order) saved once from MBTA; live trains from `/api/trains` (15 s cache, no fallback) · the map needs positions; train positions cannot be faked from a saved copy.
- 2026-11-21 · `MBTA_API_KEY` is effectively required on shared networks · without it MBTA allows 20 requests a minute per address, shared with everyone on that address (we hit this on the hackathon WiFi).
- 2026-11-21 · `/challenges/[id]` reads params inside `<Suspense>`, no `generateStaticParams`, and sets `instant = false` · quest ids are live (Cache Components rejects an empty list), and the shared nav's `usePathname()` outside Suspense fails the build on dynamic routes until it is wrapped.
- 2026-11-21 · The map is the home page (`/`); the landing page with four cards and Press Start (`features/home`) is removed · the map is the product; a menu page in front of it added a click and no information.
- 2026-11-21 · Look: atlas tokens (ivory, stone, sage, graphite, hairline, four category colours) plus Fraunces/Geist fonts; pages use the stone background; pixel font only for small accents · one coherent look with the map; the retro board-game tokens stay for older components until they are restyled.
- 2026-11-21 · Problem categories are built only from MBTA alert kinds (Service changes, Accessibility, Escalators & station, Check it's fixed); no cleanliness or crowding · there is no data for those, and the map must not show invented problems.
- 2026-11-21 · Contributing happens in a panel on the map that calls `features/challenge` (`useReport`, `api.ts`); `/challenges/[id]` stays as the shareable full page · one set of rules, no copy of the form logic.
- 2026-11-21 · /island shows Yarn World (krisyangdev/yarn-world, MIT) copied into `features/island/yarn-world/`; each stamp knits in one tier of pieces (`unlockTiers`) · a reward world that grows with real stamps; credited on the page. Added `three` and `three-mesh-bvh` to package.json.
- 2026-11-21 · Island unlocks come from the server's stamp count (`stampCount`), never from a second points system; the browser only remembers which tiers it has already shown (`tparty.island.seen:<rider>`) · avoids duplicate rewards and keeps one source of truth; losing the memory just replays the opening.
- 2026-11-21 · A new stamp knits in through a red loose thread on the quilt (one tier per pull), not by replaying the whole opening · returning visitors keep their island and only the new piece is an event.
- 2026-11-21 · Explore remembers camera and selected stop in sessionStorage (`explore/viewMemory.ts`) and restores them when the page is shown again · Next keeps pages mounted but hidden (`cacheComponents`) and a hidden MapLibre map loses its camera.
- 2026-11-21 · First visit = gate, then a GSAP dive into a small 3D district (800 m circle, real buildings raised, fog edge), then questions answered by typing in a speech bubble; the whole-city map stays one tap away ("See the whole city") · a first-time rider should land where they are, not on a city-sized map that is still loading.
- 2026-11-21 · GSAP only, no Lenis · Lenis smooths page scrolling, but the map owns the wheel (zoom) and the quest card scrolls natively; both would fight it. Revisit only if a scrolling landing page is added.
- 2026-11-21 · 3D buildings use MapLibre `distance` (not `within`, which ignores building outlines), heights capped at 46 m, only inside the district · keeps the world light and stops towers hiding stops.
- 2026-11-21 · Location is read once in the browser to pick the nearest stop; never sent, never stored · privacy, and the app needs nothing more.
- 2026-11-21 · Report: a report judged "not the city's job" cannot be overridden by the user; a wrong verdict can only be flagged for review · rejected reports must never reach 311 or add to the city's workload. See `features/report/EDGE-CASES.md`.
- 2026-11-21 · Report: emergencies (fire, injury, gas smell) are never filed; the app says "Call 911" · a 311 case is the wrong channel for an emergency.
- 2026-11-21 · Report: three case stages (Sent, In progress, Closed), because Boston's public 311 data has no "in review" or "approved" status · we show only what the city publishes. Proposed, awaiting teammate.
- 2026-11-21 · Report sends coordinates to Tada's server to look up nearby open 311 cases, and the photo to Google Gemini for the check; Tada stores neither (hosting logs may record requests); saved cases stay in the browser · reverses the earlier "location is never sent" rule. The Report copy says exactly this. Proposed, awaiting teammate.
- 2026-11-21 · Report never says "Fixed" just because a 311 case is Closed; "Fixed by" needs closure reason Resolved and a note that names a repair · the public data also closes cases as Noted or Transitioned, and some Resolved cases say "unable to process".
- 2026-11-21 · Report only names a responsible authority when we have a verified channel: Boston 311 for city categories and the MBTA (customer support) for MBTA assets; anything else is shown as an unverified guess with a limitation · we do not invent destinations. Ask Tada answers only from the photo analysis and verified nearby cases, and links a fixed list of verified pages.
- 2026-11-21 · The knitted wool art is used as a hero or a quiet accent, not on every component; functional buttons stay real HTML; My T World keeps its live 3D island and only its loading state gets the yarn ball · the knit look is the brand, but text baked into images cannot be translated, focused or read aloud.
- 2026-11-21 · My Journey, Collection and the standalone island are one page, My World (`/world`, `features/island`), and it is only the island: no counters, tabs, feeds or balances; old routes redirect · it should feel like a place you own, not a dashboard. Progress is the island growing.
- 2026-11-21 · `/api/community` and `/api/likes` (and the `likes` table) stay, but nothing shows them now · the community feed was removed from My World; the data is kept until it is clear whether Explore wants it. Riders are anonymous browser ids, so stamps could be farmed; add accounts before any real use.
- 2026-11-21 · `/api/submissions` counts likes in a try/catch · the app keeps working in a database where the `likes` table has not been created yet.
- 2026-11-21 · The little gift is a demo only (`features/island/gifts.ts`): no real partner-offer data, redemption or inventory exists, so it is labelled "Demo surprise", is not redeemable and has no code · never imply a fake offer works at a real shop. Real offers need server-side entitlements and redemption state, not localStorage.
- 2026-11-21 · No visible tokens, stamp counts or "next stamp" text on My World or in the map's contribution flow; the server still counts them · the island is the only progress the rider sees. The older `/challenge` pages still show tokens (not changed).
- 2026-11-21 · If progress cannot be loaded, My World shows what this browser last saw, grants no new piece and no gift, never records "seen" from that state, and shows one small status with Retry · a failed load must never read as zero contributions.
- 2026-11-21 · The island is a 12-step journey (`unlockSteps`), one step per contribution, using only existing pieces (per-item unlocks `isUnlocked(stage, k)`), and new pieces drop in from above on the next visit instead of needing a thread pull; the yarn-pull stays for the first opening · an empty world should look sparse and every contribution should visibly land. The old five-tier thread offer (`offerGift`) is still in `weave.js` but unused.
- 2026-11-21 · "Preview the full island" (in the help panel) includes the demo gift · a rider with no contributions yet has no other way to see the gift, which otherwise appears only after the server confirms a contribution.
- 2026-11-21 · My World is four small objects on the near side of the island (a journal and three gifts: one local treat, two discoveries), not floating cards: a compact glass label appears only on hover, focus or selection, and clicking opens a small ticket in place · the island is the experience; every object has one purpose. The clouds are back to being clouds (the gifts no longer hang from them).
- 2026-11-21 · The journal is the only place history lives (real reports and checks, truthful statuses); there is no Journey page or Community feed · history belongs in the world, and a failed load must not look like an empty journal.
- 2026-11-21 · The camera sways about 29 degrees instead of spinning a full turn, pauses on pointer-over, drag and open tickets, and sits closer (wide) or steeper (tall) · objects and labels stay attached and on screen.
- 2026-11-21 · Gifts: three, opening at 0, 5 and 10 journey steps; locked ones are faint so there is visibly more to unlock. Offers and codes are demos (`EXAMPLE-ONLY-n`); never invent a usable promo code, and tell real from demo by `Gift.demo`.
- 2026-11-21 · Each object wears a small always-visible glass tag (icon and one word: Journal, Gift, Locked) that follows it; hovering or focusing grows it into a fuller label · riders cannot tell a gift is a gift unless something stays attached to it, and a tiny tag does that without competing with the island.
- 2026-11-21 · Gifts show a REAL nearby place (cafés, bakeries, restaurants) centred on the rider's selected MBTA stop, never their own location, with distance and a map link, and NEVER an offer on it; fictional merchants carry the labelled demo offers · a real business is not proof of a partnership, and no discount may be attached to a real shop's name.
- 2026-11-21 · Nearby places come from a stored OpenStreetMap snapshot (`nearby-places.json`, built by `scripts/build-nearby-places.mjs` from the public Overpass API, credited "© OpenStreetMap contributors"), not a live call, with Google Places as an optional keyed upgrade that adds a photo · the public Overpass server took 30+ seconds and OSM data is allowed to be stored, while Google's terms forbid storing or caching place content; the snapshot is instant, free and keyless. It has no photos and goes stale, so re-run the script to refresh.
- 2026-11-21 · The first-visit tour moves the camera: it flies to the gift, then the journal, then back to the overview, and each tip disappears once its object has been opened · pointing is not enough when the object is small or off to one side; the tips and tags use one cream liquid-glass style and sit above the object so they never cover it.

- 2026-11-21 · The unlock collection is a floating gallery of the island's own objects, cloned into ONE extra preview renderer (open only while shown), not 12 canvases or static images · it reuses the real geometry and materials so the pieces match the island, costs one extra WebGL context only while open, and cannot disturb the island scene or camera. Locked/unlocked comes only from the server-confirmed count; a failed load shows nothing as unlocked.

- 2026-11-21 · There are two gift boxes, not three: a local-treat box that opens a paper voucher (picture, name, offer or place, tear line, stub, zig-zag edge, unfolds out of the gift) and an "Unlock more of your island" box that opens the collection gallery; the locked parcels and the header link are removed · each box has one clear job, and the voucher should look like a voucher. The tour's third step points at the unlock box.
- 2026-11-21 · Onboarding is one small welcome card plus two one-time hints (map pin, first ticket), kept in localStorage `tparty.onboarding` v1; a welcomed browser skips the card and does not auto-dive · the map stays the product; bump VERSION in `onboarding.ts` to show it all again.

- 2026-11-21 · The Challenge is one guided mission framework in `src/features/missions/` (overview, 3 steps, review, done); questions come from a template per alert kind plus the verified alert facts, with a generic fallback; the update text is built only from the rider's answers · so nothing in it can be invented by an AI. The old report form (five prompts, "Check with AI", revise loop) is retired from the map panel. The existing /api/review, /api/submissions and /api/verifications are unchanged and still decide what is saved and rewarded.
- 2026-11-21 · My World's first-visit tour is a rider-paced, scroll-driven walk (welcome, My Journey = journal, Your gifts, Still to explore = unlock box, Make it grow) in `features/island/Tour.tsx`, replacing the three auto-timed tips; the wheel steps the tour instead of zooming the scene while it shows · riders had no clear order for what the world's parts are; it is remembered once per browser and can be replayed from the help panel.
- 2026-11-21 · My World says what it is with translucent phone-style banners (`WorldNotes.tsx`) that roll one at a time at the top left, each floating up and covering the last, with a pill to hide them; no cloud mascot · most riders do not know what My World is; gifts are still demos, so the copy says "examples for now".
- 2026-11-22 · The journal opens as one spiral-planner page (`JournalSheet.tsx`): a blue-ruled month calendar with a sticker on each day the rider reported or checked a fix, their notes for the tapped day taped underneath, arrows and month tabs to look back · riders wanted all their reports and feedback tracked in a cute, scrapbook-like way. Sticker pictures are swappable files in `public/assets/island/stickers/` (drawn fallbacks until they exist); an empty journal, the preview, or a history that cannot load shows clearly labelled example entries (with the error kept on top when the load failed, so they are never taken for the rider's own). Tidy handwriting (Patrick Hand) is loaded inside the feature, not in the shared layout.

- 2026-11-21 · First-visit coach is its own feature (`features/coach/`), mounted from `app/page.tsx`, spread over three beats: a punchy intro naming Explore, Report and My World; the existing welcome and zoom; then Apple-notification style banners at the top right (the four problem kinds, then "every pin is a challenge") with a ring and flowing dotted line leading to the nearest problem pin; tapping a pin ends it. It reads Explore styles but edits nothing there; replay with `/?tour=1` · one big tour card was too much at once, and the Explore folder is not ours to change.

- 2026-11-21 · Explore's own one-time "Every pin is a challenge" map hint is switched off (`hintAllowed = false` in `ExploreMap.tsx`; the `MapHint` component and `mapHint` flag remain) · the coach's guide card says the same thing and two identical "Got it" boxes looked broken.

- 2026-11-21 · The "Near <stop> / N problems" box at the top left of the zoomed map is replaced by a small "Near you / N problems nearby" tag on the map beside the start stop (`ExploreMap.tsx`, strings in `world.nearYou` and `world.nearbyCount`); the top-left slot only shows the "outside the T area" / "nothing broken near here" notes when there is one · the information belongs next to the place it describes, and the coach banners need the top corners.

- 2026-11-21 · The map filter bar gets a "Near me" chip (last on wide screens, first on phones where the bar scrolls): it flies to the rider's own block, and shows the problem count there once known; with no start chosen it asks for the location once (kept in the browser) and says calmly if that fails · "see what is near me" should be one tap, not a trip back to the welcome. The filter overlay now sits above map pins (`z-20`) so a pin never draws over a chip.
